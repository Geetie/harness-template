# 通用教训库（GLOBAL-LESSONS）

> **定位**：跨项目成立、可复用的踩坑教训与工程铁律。**模板自带，新项目默认继承，无需重新踩一遍。**
> **与 `lessons.md` 的分工**：
> - `lessons.md` = 本项目踩的坑（含项目专属）→ 可晋升到本文件
> - `GLOBAL-LESSONS.md` = 已晋升的通用教训（本文件）→ 可晋升到强制门禁
> **晋升协议**：见 `.harness/LESSON-PROMOTION.md`
> **强制等级标记**：
> - 🔴 **deterministic**：已有脚本/hook 强制，违反即拦截
> - 🟡 **tool**：有脚本可查，需手动跑（`init.py` / 质量命令）
> - 🔵 **advisory**：只写规则，靠 Agent 自觉与 review
>
> **来源标记**：`[UG]` UGSimulator · `[SY]` SylvaPPT · `[AI]` AI投股工作台 · `[TPL]` 模板原创

## 0. 元原则（最高层，所有条目的出处）

### M0 · 结论的强度 = 量具观测面的强度 `[AI]`

**一句话**：**"证据链自己骗自己"是最危险的失败形态**——量具没生效 / 隔离没落地 / 统计没算上 / 规则没解析到，四者现象完全相同：**报出的结论都是"成功"**。

**四个真实形态（投股工作台"真实战争史"实证）**：

| 形态 | 现象 | 为什么骗过了自己 |
|---|---|---|
| 量具没生效 | 审计钩子"空命中不落盘" → 文件不存在 | **"钩子没生效"与"真的零写入"现象完全相同** |
| 隔离没落地 | 声称测试走 tmp 夹具，实则夹具内**零相关代码** | 注释声称已隔离（"声称已交付 ≠ 真交付"） |
| 统计没算上 | 失败行写作 `  !!FAIL {msg}`，计数器只认**行首** `PASS\|FAIL` → `FAIL=0` | 统计口径与实际输出格式错位 |
| 规则没解析到 | 归属锁 44 条规则落在 ```ownership 块**之外** → `parse_lock()` 静默跳过 | 规则"存在"于文件里，但不在解析范围内 |

**正确做法（每一条结论都要自问）**：

1. **量具必须先做阳性对照** —— 故意构造一个**应当被观测到**的输入，验证计数器真的动了、文件真的落了、日志真的打了。**阳性对照不过，禁止下"零命中/零写入/无问题"的结论。**
2. **第二观测手段交叉验证** —— 同意结论至少两个独立观测面（如"计数器条数" + `ls -lt` 看 mtime）。单观测面不足以支撑否定性结论。
3. **"已交付"必须 grep 代码，注释不算数** —— 任何"已补/已修/已隔离"的说法，必须能在代码里 grep 到实体。
4. **改完规则必须用真实入口验一条** —— 如 `parse_lock()` + `match_rule()` 实测一条命中，不能只看代码块位置对不对。
5. **失败要能被统计到** —— 输出的失败行格式必须与统计器口径一致；改输出格式时同步检查统计器。

**反面应用（很有用）**：当你要下"没有副作用 / 没有泄漏 / 没有遗漏"这类**否定性结论**时，**默认不可信**，必须补阳性对照。

### M0′ · 镜像推论：判"某个报警是误报"之前，先确认量具没坏 `[TPL]`

**一句话**：M0 讲的是"假成功"，这里讲**假失败** —— 检查器报出来的问题，
可能是它自己的观测面错了。**"修"一个误报之前，先分清是"规则太宽"还是"量具没生效"。**

**本轮两个真实对照**：

| 现象 | 我的初判 | 实际根因 |
|---|---|---|
| 关掉模块后仍报 17 条死链 | "豁免逻辑写错了" | **匹配面太窄**：引用写裸名、豁免集合是全路径，字符串永不相等 |
| 死链降到 8 条后仍剩 `delivery/*` | "还漏了" | **清单没声明文件名**：只声明目录 → 模块关闭后目录消失，反推不出文件名 |

**正确做法**：任何检查器上线/改动，都做**双向对照**：
1. **阳性对照**：造一个"应当被抓到"的样本 → 必须被抓到（验证检测面真的在工作）
2. **阴性对照**：造一个"应当被放过"的样本 → 必须被放过（验证豁免真的生效）

只有单边对照（例如只跑一遍"报 0 条就相信"）说明不了任何事 ——
**"检测器没生效"与"真的零问题"现象完全一样**（这就是 M0）。

**附加纪律**：修完后重跑**同一条**对照命令，而不是"看着差不多了"。本轮就是这么抓出第二个 bug 的。

## 1. 验证与测试

### V1 · 先复现后修复（TDD 先红后绿） `[SY]` 🟡

**坑**：直接"看着代码改"，改完测试"恰好通过"，无法区分"修好了"与"绕过了"。
**正确做法**：先写一个**失败**的测试精确复现问题 → 再改代码 → 测试转绿。测试就是根因的锁。
**自查**：这个修复有对应的失败测试吗？测试是**先红后绿**，还是改完补写的？

### V2 · 判断"是否回归"必须用隔离验证，不能凭推理 `[SY]` 🟡

**坑**：修复后出现测试失败，靠"我觉得不是我改的"下结论。
**正确做法**：`git stash push <本次改动文件>` → 跑该测试 → **仍在失败 = pre-existing 与本改动无关**。
**自查**：说"这是 pre-existing"之前，做过隔离验证吗？

### V3 · 验证必须调用生产函数路径，不能手抄逻辑 `[SY]` 🟡

**坑**：诊断脚本手抄/复制了过滤逻辑（还不含修复）→ 验证结果失真，结论完全不可信。
**正确做法**：验证脚本直接 `import` 并调用**生产函数**，而非重新实现一遍。
**自查**：我的验证脚本里，有没有一段是"把生产逻辑抄过来的"？

### V4 · 端到端"能跑通" ≠ "正确" `[SY]` 🟡

**坑**：流程无报错，但文字丢失 6 处、位置全漂移（+43px）。
**正确做法**：必须**对照标准答案量化对比**（内容/位置/字号/颜色），而不是只看"没报错"。
**自查**：我的"通过"是基于"无异常"，还是基于"与标准答案一致"？

### V5 · 有异步状态机的 UI 测试，找"同步可观测信号"做即时断言 `[UG]` 🟡

**坑**：测试用"固定 950ms 等待 + 数量检测"与组件 800ms 复位 setTimeout 赛跑 → 偶发失败（flaky）。
**正确做法**：①先找**状态变化的同步可观测信号**（如 class 出现）做即时断言；②只有"不配对"才等复位；③锚点操作做**幂等重试**。
**通则**：**任何 sleep 与组件定时器赛跑都是 flaky 温床**。优先消灭等待。

### V6 · 测试隔离铁律：读生产状态必须注入 tmp 路径 `[AI]` 🔴

**坑**：模块级常量固化的路径（`notifier.ALERT_FILE` / 单例 / 硬编码）无注入点 → 测试"假装在测"**实际每次写生产**，且**故障随时间自然出现**（数据一陈旧就红）。
**正确做法（两层隔离）**：
- **面**：环境变量级单点注入（如 `XXX_TEST_LOG_DIR` 由 test_runner 统一注入，覆盖全部测试文件）
- **点**：注入点级往返范式 `inject_xxx(path=None) -> old`
- **单例/日志器必须在 `@property` 里懒解析路径** —— import 期固化 → 注入失效且跨日不滚动
- 节点依赖抽 `Deps` 钩子，**禁止在节点内内联 import 业务模块直调**
**自查**：跑测试时，有没有任何一处写了工作区真实路径？

### V7 · 失败行格式必须与统计器口径一致 `[AI]` 🔴

**坑**：失败行写成 `  !!FAIL {msg}`，统计器只认**行首** `PASS|FAIL` → 失败被静默计为 `FAIL=0`，还被归到另一个文件。
**正确做法**：统一失败行格式；**改输出格式时同步检查统计器**；统计口径写进检查清单。
**通则**：**凡是"计数/统计"逻辑，都要用阳性对照验证它真的能数到**（见 M0）。

### V8 · 断言必须匹配稳定标识 `[SY]` 🟡

**坑**：`count('<rect id="bg01"')==1` 依赖"标签+属性紧邻"的脆弱格式；上游加了 `data-z` 属性 → 断言失配误报。
**正确做法**：断言匹配**稳定标识**（如 `id="bg01"`），不匹配相邻属性/格式细节。

### V9 · 测试基线防漂移 `[UG]` 🟡

**坑**：基线数字散落多处（`init.sh` / `AGENTS.md` / `progress.md`），实测发现 `4630 / 4614 / 4607 / 4017` **四处不一致**，无法判断"最新对不对"。
**正确做法**：基线**单一权威源**（`.harness/config.json`），其余位置引用而非复写；基线变化必须同步更新所有引用点。

## 2. 状态与数据

### S1 · 不要用"文本猜"来改世界状态 `[UG]` 🔴

**坑的谱系**：位置（正则猜移动意图）、时长（文本猜活动）、日结束、专业、关系门槛……全部是同一根因的不同形态，逐个修了 20 轮。
**正确做法（架构铁律）**：凡是「LLM 文本/信号 → 写世界状态」一律改 **「显式结构化声明 + 系统校验（词表/阈值/阶段机）+ 确定性默认兜底」**。
- 三个层次：**枚举声明**（词表）/ **数值声明** / **布尔声明**
- **未声明一律用确定性默认，不猜文本**
- **检测层（不写状态）可保留启发式，但要标注来源**
**自查**：这段代码是在**读文本推断状态**，还是在**读一个显式声明**？

### S2 · 唯一写者 ≠ 值域安全 `[UG]` 🔴

**坑**：`set_location` 是唯一写者，但**无值域校验**；上游三套值域混写（显示名/实体ID/房号），随时可复发。
**正确做法**：**唯一边界写入口必须加值域门禁** —— 非法值**拒绝写入 + 告警**，不静默接受。
**通则**：「唯一写者」铁律只保证"谁写"，**不保证"写什么合法"**。两者都要。

### S3 · 值域变更必须全链路 grep 读写两侧 `[UG]` 🔴

**坑**：改了某个字段的值域，只改了写入侧，读侧（比较/查找/映射/UI 显示）全部失配 → 记忆断链、映射 miss、玩家看到原始 ID。
**正确做法**：改一处值域，**grep「所有写入点 + 所有消费端」对照**，两侧同时改。收尾再 grep 一次旧值域残留。

### S4 · 派生字段必须与事实源同源重推 `[UG]` 🔴

**坑**：用快照 A 覆盖字段 B 的一部分，但 B 的**派生字段**（星期/季节/周末标记）沿用旧值 → 日期与星期矛盾。
**正确做法**：任何"用 A 覆盖 B 的部分字段"的逻辑，检查**被覆盖字段的派生结果是否也要重算**。**date 是唯一事实源**，其他一律 derive。
**自查**：这里有硬编码的季节/星期/时段吗？它应该由哪个事实源推导？

### S5 · 只增不减的集合，注入/校验侧必须封顶 `[UG]` 🔴

**坑的形态**：状态文件、伏笔日志、回响日志、记忆文本、上下文注入段 —— 全部"只增不剪"，运行期线性增长。
**正确做法**：
- 存储侧可保留全量（去重/回收依赖全量语义），但**注入侧必须切片/预算**
- **token 预算式裁剪**（从最新开始累加，超预算折叠为"更早 N 条从略"），而非按天数硬编码
- 出口加**估算断言**（如 0.7 token/字，阈值告警）形成定量护栏
**通则**：凡"只增不减"的集合，都要问「注入/校验侧如何封顶」。

### S6 · 压缩机制建了，渲染端必须消费 `[UG]` 🔴

**坑**：压缩/摘要机制已实现，但渲染端**全量 map 不消费压缩**（近 7 天原文峰值 8k+ token，是 prompt 最大头）→ 压缩收益在渲染端被绕过。
**正确做法**：建完压缩机制，**必须回到消费端确认它真的被调用**；出口加 token 估算断言。
**通则**：这是"接线失败"的一种——**机制存在但没接上**。

### S7 · 定量断言必须以真实 delta 为准 `[UG]` 🟡

**坑**：审计 note 用"归一化后数组长度"报"本轮 1 条已入库"，但真实 `count` 未增 → note 与 degree 自相矛盾。
**正确做法**："已入库/已新增"类断言，数值必须用**真实 count 变化（delta）**，且与另一处口径可互相印证。

### S8 · 静默兜底让系统在错误状态下继续跑 `[TPL]` 🔵

**坑**：`return 默认值` / `except: pass` / `|| fallback` 让错误被吞，问题在很远的地方才爆出来。
**正确做法**：**兜底可以存在，但必须显式声明"我走了兜底"** —— 每一处走兜底的分支都要置标记，且**不看兜底覆盖范围大小**（局部字段兜底也要标）。
**通则**：`[AI]` 的"统计口径静默吞失败"、`[TPL]` 的"失败要响亮"是同一族。

### S9 · 兜底/降级路径也必须满足主契约 `[UG]` 🔴

**坑**：兜底模板不带 `time_span` → 时间停滞；兜底模板无位置意识（室内套用户外感官）→ 自相矛盾。
**正确做法**：**任何生成路径（主路径/LLM/兜底）都要满足同一份契约**。兜底不是"暂停"，是"内容降级"。
**自查**：兜底分支走完后，主路径所有的必备字段/不变量都成立吗？

### S10 · 模板文本不写具体钟点/日期，写相对意象 `[UG]` 🟡

**坑**：感官模板写死"六点钟天就大亮了"，玩家时钟 07:48 时被误读为时间错配。
**正确做法**：模板写**相对意象**（"亮得特别早"），不写绝对钟点/日期 → 泛化到任意时刻触发。
**通则**：模板/文案里凡是**绝对量（时间/编号/数量）**，都要问「换个上下文还成立吗」。

### S11 · 确定性模板的随机种子要够区分度 `[UG]` 🟡

**坑**：兜底模板只用 `day_index` 做 seed → 同一天两次兜底输出**逐字相同**（玩家 97 分钟内看到两段一样的话），且重复文本污染后续上下文。
**正确做法**：seed 混入更多维度（如 `day_index × 1000 + 分钟`）保持确定性；**变体数要 > seed 空间碰撞概率**。
**自查**：同一维度内多次调用，能区分开吗？

### S12 · 路径规范化禁用 `lstrip("./")` `[TPL]` 🔴

**坑**：`path.lstrip("./")` 看着像"去掉前缀 `./`"，实际 `lstrip` 的参数是**字符集**——
它会把开头所有的 `.` 和 `/` 全部剥掉。于是 `.harness/x.md` → `harness/x.md`，**前导点被吃掉**。
实测后果：模块归属匹配、豁免比对全部失效，报出一堆"不属于任何模块""引用找不到"的假阳性，
而且**单测一条不报**（因为大多用例路径不以点开头，恰好避开）。

**正确做法**：
```python
def norm_rel(p):                 # ✅
    p = p.replace("\\", "/")
    while p.startswith("./"):
        p = p[2:]
    return p
```
（或 `re.sub(r"^\./+", "", p)`；`pathlib.PurePosixPath` 亦可。）
**绝不要**用 `lstrip`/`rstrip` 做前后缀剥离 —— 它们都是字符集语义。

**自查**：这个"去前缀"函数，我拿以点开头的路径试过了吗？

### S13 · 工具描述自身时会被自己的规则打中 `[TPL]` 🔴

**坑**：一个**防占位符**的门禁，拿本仓库自检报 14 条 ERROR —— 全是"讲解占位符"的文字：
`AGENTS.md` 写「不写 TODO / NotImplementedError」这条**规则本身**被判违规；
`README.md` 讲「没有 DoD 会产出 Incomplete Implementation」的**定义**又被判违规。
**这不是文档写错了，是扫描范围设计错了**：`.md` 里出现 `TODO`/`NotImplementedError`，
绝大多数情况是在**讨论它们**，不是在犯它们。

**正确做法**（两层）：
1. **按文件类型选规则**：文档（`.md`/`.txt`）只跑"模板占位符填没填"，不跑代码语义规则
2. **行内豁免指令**：`guard:allow` 注释，用于"必须提到关键词"的正文与脚本注释。
   比自动识别"这句话是不是在讲规则"可靠（自然语言判断做不到零误判），且可审计。

**自查**：我的门禁拿自己跑过吗？报出来的每一条，是违规还是"在描述违规"？

### S14 · 读文件失败被静默吞掉 = 检查器整体空转 `[TPL]` 🔴

**坑**：`read(path)` 捕获 `OSError` 后返回 `None`，各检查统一写
`if not content: continue`。于是**"文件没读到"与"文件读到且没问题"在输出上完全一致**
——都是"这条不报"。实测踩到：测试夹具里传了相对路径（真实调用链传的是
`collect_docs` 产出的绝对路径），10 个检查函数**全部静默跳过**，
界面显示"✅ 未发现漂移 / 0 ERROR"，实际一条都没扫。这是 M0「假成功」的教科书形态。

**正确做法**：
1. **失败要留痕**：`read()` 把每次失败记进 `SKIPPED` 列表，结尾统一打印
   「⚠️ N 次读取失败（被静默跳过 → 其结果未纳入检查）」，并给 `--explain-skip` 开关。
2. **契约写进 docstring**：明确"本函数只吃绝对路径"，并让唯一生产调用方
   （`collect_docs`）天然满足。
3. **"全绿"要与"扫到了几份文件"一起看** —— 只报 ERROR/WARN 数量、不报
   扫描规模，等于给了个可以骗人的绿灯（本仓库输出里 `扫描 N 份文档` 就是为此存在）。

**自查**：这个检查器报 0 条时，我能证明它**真的扫过东西**吗？

## 3. 环境与工具链

### E1 · 不要用管道截断启动长驻进程 `[UG]` 🔴

**坑**：`next dev 2>&1 | head -20` → head 退出关闭 stdout 管道 → 进程收 SIGPIPE 被杀，约 10 秒后死，端口残留 404。
**正确做法**：长驻进程日志**重定向到文件**（`... > /path/x.log 2>&1`），不要管道给 `head`/`tail`。
**排错**：`EADDRINUSE` 先 `netstat -ano | grep :端口` 找 PID，再 `taskkill /PID x /F`。

### E2 · 包管理器唯一标准，禁止混用 `[UG]` 🔴

**坑**：npm/pnpm 混用破坏 `node_modules`（@next/swc 版本漂移 → 页面 500；顶层残留 webpack 干扰编译）。
**正确做法**：**项目内声明唯一包管理器**，禁止另一种；删除对方 lockfile 并禁止再生成；`package.json` 不设 `packageManager` 字段（防 corepack 强制）。

### E3 · 构建缓存损坏要整体 rename，不要原地删 `[UG]` 🟡

**坑**：dev server 强停残留 dangling 类型文件；webpack pack cache 损坏报 `invalid code lengths set`。
**正确做法**：缓存目录损坏时**整体 rename**（如 `.next` → `.next.bad-tmp`）后重建；dev 场景可只删子目录（如 `.next/cache`）。
**通则**：**破坏性操作留后路** —— rename 可回滚，`rm` 不可。

### E4 · 并行会话 git 铁律 `[UG]` 🔴

**坑**：多 agent/多会话并行时对 shared 分支执行 `git reset` → 已提交 commit 脱离分支链、改动散落 staged 区，差点互相覆盖。
**正确做法**：
- 禁止对 shared 分支执行 `git reset` / `rebase` / `amend` / `add -A`
- 提交一律 `git commit --only <自己的文件>` 做隔离
- 需要重组历史 → **开新分支**
- 发现 staged 区有他人文件 → **保持不动**，不要顺手提交

### E5 · 大 git 操作给足超时，且必须有远端备份 `[AI]` 🔴

**坑**：批量操作超时被杀 → **对象库损毁**，`status` 全 A / unborn。
**正确做法**：
- 大操作一律**后台执行 + 超时给足**（如 600s），不要用默认短超时
- 仓库**必须有远端备份**，这是可恢复的前提
- 高风险窗口禁 `git stash`

### E6 · 虚拟层/沙箱路径禁建跨层链接 `[UG]` 🔴

**坑**：手动创建跨【真实磁盘 ⇔ 虚拟缓存层】的 junction/symlink 绕行 `EBUSY` → 目录在终端/git 视角消失（真实数据完好），只能重启 IDE 恢复。
**正确做法**：**严禁在跨虚拟层路径建 junction/symlink**；遇 `EBUSY` 先排查占用进程；删除链接**严禁 `-Recurse -Force`**。

### E7 · 并行编辑同一文件必须串行 `[AI]` 🔴

**坑**：并行 Edit 报成功但编辑**没落盘**（两次实锤，静默丢编辑）。
**正确做法**：同一文件多处修改**必须单次串行**；改后 **grep 验证真的改了**。
**通则**：这与 M0 同源 —— "工具报成功"不等于"磁盘真改了"。

### E8 · 外部依赖不可信，需多源降级 + 契约冻结 `[AI]` 🟡

**坑**：外部数据源字段/口径**悄悄变了**，代码还按旧的跑（同字段跨期口径分裂，同名指标双口径差 2 倍）。
**正确做法**：多源降级 + **契约冻结**（把关键 schema/口径显式写下来并校验）+ 失败重试 + **口径坑台账**。

### E9 · 单一通路必然断供，需要冗余 `[AI]` 🔴

**坑**：某数据源在某环境不可直连 → 关键数据缺失，但流程"没报错"。
**正确做法**：**多通路冗余 + 失败显式标注**（缺数返回缺失/未核实，不脑补；豁免清单如实标注）。
**通则**：**关键能力只有一条路 → 必然断**。

## 4. 流程与协作

### P1 · 改代码前先跑基线 `[TPL]` 🔵

**一句话**：不知道"原来是对的"，就无法判断"现在是对的"。

### P2 · 修复必须是根因修复，不是绕过 `[SY]` 🔴

**三种必须禁止的"假修复"**：

| 假修复 | 形态 | 为什么不行 |
|---|---|---|
| **数据补丁** | 只改产物数据（如手改检测结果 bbox），不改检测代码 | 重跑必然复发 |
| **放宽容差/跳过校验** | 用 `strict=False` / 跳过 QC / 改标注类型绕过校验 | "通过"无效 |
| **单图/单点特判** | 给某个具体输入打补丁 | 换个输入必复发 |

**正确做法**：修复落在**生产逻辑**；校验门禁**不可被调用方关闭**（门禁下移冻结）。
**自查**：
- 这个修复重新跑一遍生产流程还成立吗？
- 我是靠**放宽阈值/跳过校验**让它通过的吗？
- 这是通用逻辑，还是给某个具体输入打补丁？

### P3 · 架构切换必须删代码，不是只改文档 `[SY]` 🔴

**坑**：架构已废止，但只改了文档声明 → 旧代码长期残留（12000+ 行），测试持续为其累积（大量只测旧模块的测试）。
**正确做法（固定顺序）**：**删除旧生产代码 → 清理其测试 → 全量验证 → 提交**。
**自查**：声明的废止架构，对应生产代码**删了吗**？其测试**清了吗**？

### P4 · 改动不超出任务范围 `[TPL]` 🔵

**一句话**：发现相邻问题**单独报告**，不顺手改（顺手改是回归 bug 的主要来源）。

### P5 · 不确定就问，不要自行假设 `[TPL]` 🔵

**一句话**："先问再做"的成本远低于"做完再改"。

### P6 · 写结构化数据用工具，不手拼 `[TPL]` 🔴

**一句话**：JSON/YAML 手拼易损坏；**写后必须能 parse**。并发写同一文件必须串行。
**实证**：`[UG]` 并发工作流写同一个 `feature_list.json` → 重复 id + 裸换行导致 JSON 损坏。

### P7 · 每个新任务开新会话 `[TPL]` 🔵

**一句话**：长会话开头的约定到后面会被遗忘（context rot）。

### P8 · 文档漂移必须靠机制检测，不能靠人记 `[UG]` 🔴

**坑**：同一事实散落多处（基线数字 4 处不一致、元规范 147 行比宪法 145 行还长、"已废止规则表"留在宪法里）。
**正确做法**：**单一权威源 + 引用而非复写 + lint 检测一致性**。

### P9 · 破坏性/删除操作交给人执行 `[峰宝]` 🔵

**一句话**：需要权限审批的删除（废弃 worktree、整个目录）**直接告诉人要删什么**，不要自己死磕或绕过。

### P10 · 全量回测前先问"有必要全量吗" `[峰宝]` 🔵

**一句话**：**能精准测特定范围就不要全量**。全量是成本最高、信息密度最低的手段。

### P11 · 交付前必须自审产物，达标才交 `[UG]` 🔵

**用户定义的"产物自审三铁律"**：
1. 自己写的**前端页面** → 必须**在浏览器里打开截图自审**，从用户视角反思视觉问题，修完再交付
2. 自己生成或调用外部生图 API 的**图片** → **必须自己读图审查**（乱码/文字重叠/解剖错误/空间关系/风格不符），抓到痛点后反思提示词并针对性修
3. **满分 100 分自评，不做到 75 分不交付**

### P12 · 开发前先想清输入输出分布与错误边界 `[峰宝]` 🔵

**一句话**：任何开发先明确**输入从哪来、输出去哪、出错怎么办**；**返回结果不允许静默**，必须显式声明发生该结果的原因。

### P13 · 协议升级先做最小可测的 A/B，数据说话再动生产 `[UG]` 🟡

**坑**：凭"感觉更好"升级 prompt 协议/模型参数。
**实证**：真实 LLM A/B（8 场景 × 3 方案）证明某升级质量持平但延迟 -22%（安全）；而"显式 thinking"反而 parse 率掉到 88%、延迟更高（**创作类任务 thinking 无收益**）。
**正确做法**：**先做脚本化、离线可测的最小 A/B，用数据决定是否上生产**。

### P14 · LLM 协议字段的强制约束不能只靠 prompt 措辞 `[UG]` 🔴

**坑**：prompt 加"⚠️ 缺失即废稿""必须以上述 JSON 形式" —— LLM 仍不遵守（长 prompt 中段字段在生成注意力里权重低），连续两批失效。
**正确做法**：**后端结构性断言 + 违约重试/降级标注**。状态由系统校验执行，不是 prompt 求 LLM 自觉。
**通则**：与 S1（声明化）同源。

### P15 · 凡"LLM 主动声明"的机制，都要问"不声明时怎么兜底" `[UG]` 🔴

**坑**：两段式检索是 LLM 主动声明，**不查询则关键信息缺失**（机制看似正常，实际静默降级）。
**正确做法**：**系统侧确定性兜底**（系统强制拉取必要上下文，不依赖 LLM 自觉）。

### P16 · prompt 修复写结构规则，不写词表豁免 `[UG]` 🔴

**坑**：给 LLM 写"门口应判 X"这类具体词豁免 → LLM 对含该词的**合法**情况也误判；反例词越多越保守，新形态照样漏。
**正确做法**：**判定标准写成结构语义**（如"target 必须命中可落位地点清单"），示例只作解释，LLM 可泛化到未见过的情形。
**自查**：这个修复是**结构规则**还是**词表豁免**？是后者就转换。

### P17 · 系统性扫描优于点状修复 `[UG]` 🟡

**一句话**：**"一个机制覆盖一族"** —— 点状校验是同类问题的再生源。修一个问题时，全文件/全仓审计同类问题。

### P18 · 接线问题要看真实调用链 + 对比注释与代码 `[UG]` 🔴

**坑**：审计发现"零调用点"就判死代码 —— 但真实触发走的是**事件驱动**路径，函数是遗留死代码而非缺失接线；反向也有：注释声称"已应用"但代码里并未真正应用。
**正确做法**：**两条都要查** —— ① 追真实调用链；② 对比注释声明与代码实际行为。两者不一致就是问题。
**通则**：这是 M0 的"注释不算数"在接线场景的应用。

### P19 · 复用型工程同步要查五处，typecheck 通过 ≠ 语义对齐 `[UG]` 🔴

**坑**：复用生产 core 的独立工程（demo/实验室），生产语义变了但 demo 没跟 —— `typecheck` 全绿，**语义已经漂了**（摘要器未注入但注释声称已激活、注入段映射表缺 6 个新段、调用被误标来源、镜像不反映新档位、类型定义了但从不发射）。
**正确做法（同步清单五查）**：①装配差异（与生产装配点逐一比对注入项）②prompt 段映射表 ③遥测 phase 推断 ④来源镜像 ⑤环境语义。
**自查**：`typecheck` 通过**不等于**语义对齐 —— 有没有比对生产装配点？

### P20 · 计划文档里提及特殊字符要防解析器误伤 `[UG]` 🟡

**坑**：计划文档/注释里写 `ENERGY_*/STRESS_*/GPA_*` → esbuild 把 `*/` 当**注释结束符** → "Unterminated regular expression"；CSS 注释里写 `bg-*/text-*` → 注释提前闭合，`@theme` 未注册（**变量存在但 utility 完全不生成，无报错**）。
**正确做法**：文档/注释中提及含 `*/` 的片段用空格分隔（`ENERGY_* / STRESS_*`）。
**排错**：`@theme` 变量在但 utility 不生成 = theme 未注册，**优先查注释**。

### P21 · 一份配置只能有一个真相源，多份必然漂移 `[TPL]` 🔴

**坑**：模块→文件的映射在三个脚本里各写了一份（生成侧 / 体检侧 / 检查侧）。
生成的漂移了检查的、检查的漂移了生成的：**生成侧漏路径 → 关模块时文件没被过滤（留残骸）；
检查侧漏路径 → 死链检查不认"模块已关闭"，产生几十条噪音**。两边都"看起来正常"。

**正确做法**：抽一个 `module_manifest.py` 作为**唯一声明处**，三方 `import` 它。
配套纪律：**模块要声明自己拥有的每一个文件**（不是只声明目录）——
目录无法反推文件名，且模块关闭后目录已不存在，更推不出来。

**自查**：同一份映射/枚举，仓库里有几处定义？> 1 处就是定时炸弹。

### P22 · 可插拔的正确姿势：让规则认识"未启用"这个状态 `[TPL]` 🔴

**坑**：关掉某模块后，其余文档里**必然**还有指向它的引用（清单要列举模块、总览要说明分层结构）。
一开始靠"生成时清理文档引用"消死链 —— 治标：清不干净（表格单元格、行内提及），
而且删掉后文档就说不清"这个模块存在可选"。

**正确做法**：**检查规则本身要能读模块开关**，跳过属于已关闭模块的引用。
清理引用只是辅助（保留可读性），不该是主要手段。
配合铁律：**降级必须显式**（打印 `[SKIP] 原因`），且**依赖缺失自动补齐时要告警**。

**自查**：我的检查规则认识"这个模块没启用"吗，还是把它的缺失当错误报？

### P23 · 清单里的每一条路径，都必须在磁盘上能被证实 `[TPL]` 🔴

**坑**：模块清单里声明了 `.githooks/hooks.json`——这个文件**从不存在**，
是早期凭印象写下的臆想路径（真实文件是 `.harness/hooks/hooks.json`）。
后果有三层：① init 的"必需文件清单"永远比对不上；② 可插拔自检报一条**假缺失**；
③ 最坏情况会让人去"补"一个本不该存在的文件。

**正确做法**：清单（`module_manifest.py` 的 `owned`）是**声明**，声明必须可被磁盘核验。
加一条自检：清单里每个路径 `os.path.exists()` 必为真，否则报错。
与 P21 同理 —— **清单本身也是一个真相源，它必须与磁盘事实一致**。

### P24 · 换一种输入写法，就要重做一遍对照 `[TPL]` 🟡

**坑**：验证 L010 时，夹具传了**相对路径**，而真实调用链传的是
`collect_docs` 产出的**绝对路径**。测试"通过"（0 findings），
但通过的原因是**读不到文件而静默跳过**（见 S14），不是逻辑正确。
即：测试结论对，测试过程骗人。

**正确做法**：验证检查器时，夹具的输入形态必须**与生产调用链一致**
（同样的路径风格、同样的文件布局、同样的调用入口）。
验证脚本要**直接调生产函数**（同 V3），且输入要"长得像真的"。

**自查**：我这个测试里，被验对象的输入是手搓的，还是从真实入口一路传下来的？

### A1 · 废止的规则不能留在权威文档里 `[UG]` 🔴

**坑**：宪法里留着 17 行"已废止规则表" → 新 Agent 读到会困惑"这条到底还算不算数"。

**正确做法**：**状态机 + 双向指针**（旧决策标 `superseded by ADR-NNN`，新决策写 `supersedes ADR-MMM`）。详见 `.harness/DECISION-PROTOCOL.md`。
