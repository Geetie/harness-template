## 七、拟升级为**强制门禁**的候选（进 pre-commit / 脚本）

只有**判定方式明确**的条目才能上强制。以下是我筛出的 20 条中**最适合先做**的 6 条，附判定方式草案：

| 规则 ID | 对应条目 | 判定方式 | 误报风险 |
|---|---|---|---|
| **G001** | S2 值域门禁 | 检测"唯一写者函数体内是否有值域校验/拒绝分支" | 中（需要模式识别） |
| **G002** | P3 废止代码 | 文档声明废止的模块 → 对应源码目录是否仍存在 | 低 |
| **G003** | A2 决策指针 | ADR 状态为 `superseded` 时，必须有 `superseded_by`；被取代方必须有反向指针 | 低 |
| **G004** | V9 基线一致 | `.harness/config.json` 的基线数字 vs 文档中出现的数字，不一致即报 | 低 |
| **G005** | S5 状态封顶 | 状态文件行数/字节超 `STATE_LIMITS` 即报（已有实现，Round 1） | 低 |
| **G006** | P20 `*/` 误伤 | 文档/注释中出现 `X_*/Y_*` 或 `bg-*/` 等模式 | 低 |

> **其余 🔴 条目的处理**：写进 `GLOBAL-LESSONS.md` + `AGENTS.md` 铁律区（advisory 级）+ 审计 prompt checklist，**不强行上 hook**（误报风险高会让人关掉门禁 —— 这是你的"降噪即有效性"原则）。
