# 决策演进协议（DECISION-PROTOCOL）

> **解决的问题**：项目从零开始，决策和设计持续演进。**架构一升级，昨天的文档就不可再用。**
> 本协议保证：**任意 Agent 接手时，读到的都是最新信息；读到过时信息时，它会明确知道"这是过时的"。**
>
> **本文件是协议正文。决策台账在 `planning/DECISIONS.md`，决策正文在 `planning/decisions/`。**

---

## 0. 为什么需要它（先看失败案例）

**UGSimulator 实测暴露的三条断链**（12 条 ADR，无一例外）：

| 断链 | 实测证据 | 后果 |
|---|---|---|
| **决策 → 落地** | `ADR-012` §5 验收标准 5 条全是未勾选的 `[ ]`；§4 明说"步骤 2 留到 Gap 3 实现时一并做" | **没人知道这条决策到底施行了没有**。新 Agent 读到 ADR 会以为"已经是这样了" |
| **决策 → 取代** | 12 条 ADR **没有一条标注 `superseded`**。ADR-011 提到某体系废弃，但那是"新决策宣布旧的死"，**没有反向指针** | 新旧决策并存，**Agent 无法判断哪个有效** |
| **决策 → 认知** | `AGENTS.md` 只引用了 1 条铁律，**没有一行说"本项目当前有 12 条决策，其中 N 条未落地"** | Agent 不知道决策全貌，可能按已废的旧约定干活 |

**根因**：模板此前只规定了「决策怎么写」，**没规定「决策怎么活」**——状态怎么变、失效怎么标记、欠账怎么追踪。

## 1. 三件套结构

```
.harness/planning/
├── DECISIONS.md              ← 台账（索引表 + 状态机 + 欠账清单）★单一权威源
├── decisions/
│   ├── ADR-000-TEMPLATE.md   ← 决策正文模板（含 YAML frontmatter）
│   ├── ADR-001-*.md          ← 决策正文（一条一文件）
│   └── ...
├── CONSTITUTION.md           ← 项目宪法（最高原则，决策不得违反）
└── SPEC-TEMPLATE.md          ← 需求/设计/任务三段式
```

**分工铁律**：
- **台账（`DECISIONS.md`）= 唯一权威源**。要判断"某条决策现在什么状态"，**只查台账，不查正文**。
  - 理由：正文可能很多份，状态散落各处必然漂移。台账集中，且由脚本校验（L008/L009）。
- **正文（`decisions/ADR-NNN-*.md`）= 决策的完整论证**。Agent 需要"为什么这么定"时才展开读（渐进式披露）。

## 2. 状态机（核心）

**每条决策必须处于以下五态之一**：

```
                    ┌──────────────────────────────────────┐
                    │                                      │
  proposed ──→ accepted ──→ partial ──→ accepted           │
   （提议）     （已接受）   （已决未落地）  （欠账还清）        │
                    │                                      
                    ├──→ superseded  （被后续决策取代）★终态
                    └──→ rejected    （明确否决）      ★终态
                                      
  deprecated （自然失效：环境/依赖变化导致不再适用，无替代者）★终态
```

| 状态 | 含义 | 必须附带什么 | 可否违反 |
|---|---|---|---|
| `proposed` | 提议中，未生效 | 待决问题 + 备选方案 | 可（未生效） |
| `accepted` | **已接受且已落地** | 生效日期 + 落地证据（文件/行/commit） | **不可违反** |
| `partial` | **已决但未完全落地** | **必填：`gap`（还差什么）+ `blocked_by`（为何没做）** | 部分不可违反 |
| `superseded` | 被后续决策取代 | **必填：`superseded_by: ADR-NNN`** | 不可违反（已被新决策覆盖） |
| `rejected` | 明确否决 | 否决理由 | 不作为约束 |
| `deprecated` | 自然失效（无替代） | 失效原因 | 已在失效日之后不再约束 |

### ⚠️ 三条铁律

**铁律 1 · `partial` 必须带 gap，否则违反 = ERROR**
> "已决未落地"是最危险的状态——**看起来已经定了，实际没做**。必须写明差什么、为什么没做，否则新 Agent 会以为已经生效。
> 这正是 `ADR-012` 的形态：它自己写了"留到 Gap 3 一并做"，但**没有机器可查的标记**，于是没人追踪。

**铁律 2 · `superseded` 必须双向指针，否则违反 = ERROR**
> 旧决策写 `superseded_by: ADR-015`；新决策写 `supersedes: [ADR-010]`。**缺任一侧 = 链路断裂**，Agent 可能顺着旧指针继续走。
> 校验规则见 §5 的 `L008`。

**铁律 3 · 状态只在台账改，正文头部的状态是副本**
> 两边不一致时**以台账为准**，lint 会报不一致（`L009`）。
> 为什么允许副本存在：正文单独被读到时（如被 grep 到、被链接点开），Agent 也应能立刻看到状态。

## 3. 失效水位（解决"昨天的文档还能不能用"）

**核心机制：依赖声明 → 自动标 STALE**

每份**治理文档**（`AGENTS.md`、模块 AGENTS.md、`docs/` 下的现行设计文档）可声明头部依赖：

```markdown
<!-- depends-on: ADR-010, ADR-012 -->
```

**检测逻辑**：
```
若某文档 depends-on 的决策中，存在状态为 superseded / deprecated 的
   → 该文档被判定为 STALE
   → 在文档顶部插入/更新 STALE 横幅：
      > ⚠️ **STALE**：本文件依赖的 ADR-010 已被 ADR-015 取代，相关结论不可直接使用。
      > 请先阅读 DECISIONS.md 确认现行决策。
```

**为什么不直接删文档**：
1. 删不干净 —— 引用它的地方会变成死链，且历史论证有价值
2. **"还在，但头顶有 STALE 警告"比"不见了"更安全** —— Agent 能看见"这里有个坑"，而不是无声地读到过时内容
3. 归档区（`archive/`）保留全文，供追溯

### 两档处置

| 情境 | 处置 |
|---|---|
| 结论**已被取代**，但有历史价值 | 移入 `archive/`，原位置留一行指针（`已归档 → archive/xxx.md（原因：ADR-015 取代 ADR-010）`） |
| 结论**部分仍有交** | 留在原位，头顶加 STALE 横幅，**明确标出哪部分失效** |

## 4. 给 Agent 的三条行为准则（写进 AGENTS.md）

**准则 1 · 动手前先读台账**
> 接受任务后，**必须先读 `.harness/planning/DECISIONS.md` 的状态表**，确认：① 有哪些现行决策约束我的任务；② 有没有 `partial` 决策的欠账正好是我这次能还的。

**准则 2 · 遇到 STALE 文档不要直接用**
> 读到带 STALE 横幅的文档 → **停，先读台账确认现行决策** → 用新决策的结论做事 → 顺手更新该文档或报告给人。

**准则 3 · 做了架构决策必须落台账**
> 任何改变架构/接口/数据模型/依赖的决定，**不是"改完代码就算"**，必须：
> ① 新建 `decisions/ADR-NNN-*.md`（用模板）
> ② 更新 `DECISIONS.md` 状态表
> ③ 若取代了旧决策，**两侧都写指针**
> ④ 若决定了但没做完，标 `partial` 并写 gap
>
> *"我改完了" ≠ "决策记录已更新"* —— pre-commit 会检查。

## 5. 机器校验（L008 / L009 / L010）

融入 `harness_lint.py`，**默认进 pre-commit**：

| 规则 | 检查 | 级别 | 判定方式 |
|---|---|---|---|
| **L008** | **失效指针完整性** —— `superseded` 决策必须有 `superseded_by`；被取代方必须有反向 `supersedes`；指针指向的 ADR 必须存在 | **error** | 解析台账 + 正文 frontmatter，双向比对 |
| **L009** | **台账 / 正文状态一致性** —— 同一 ADR 在台账与正文里的状态必须一致 | **error** | 两处解析后比对 |
| **L010** | **引用已失效决策** —— 文档 `depends-on` 里出现 `superseded`/`deprecated` 状态的 ADR | **warn**（首轮不拦提交，避免打断）→ 稳定后可升 error | 建立"失效 ADR 集合"，扫依赖声明 |
| **L011** | **partial 决策的 gap 未填** —— 状态为 `partial` 但 `gap` 字段为空 | **error** | frontmatter 字段检查 |

> **为什么 L010 首轮只 warn**：按"降噪即有效性"原则 —— 若立刻拦提交，遇到历史项目升级时会一次报几十条，人会直接关掉门禁。**先让它可见，稳定后再升格。**

## 6. 与"从零开始"项目配合的完整流程

**Phase 0（开工）**：
```
① 建 .harness/planning/decisions/ 与 DECISIONS.md（模板自带空表）
② 写 ADR-001 记录最初的技术选型（技术栈/框架/数据存储）→ 状态 accepted
③ 在 AGENTS.md 顶部加 depends-on 声明（如 depends-on: ADR-001）
```

**Phase N（每次做架构决策）**：
```
新建 ADR → 落台账 → 若取代旧的则双向打指针 → 若未做完标 partial + gap
```

**Phase N（每次决策被推翻）**：
```
① 新建新 ADR（写明 supersedes: [旧]）
② 旧 ADR 状态改 superseded + superseded_by: 新
③ 找出所有 depends-on 旧 ADR 的文档 → 逐个加 STALE 横幅或归档
④ 跑 harness_lint.py --only L008,L009,L010 确认无断裂
```
> 步骤 ③ 是**最容易漏的**，也是"昨天文档过时"问题的直接答案 —— **不靠人记得改，靠 lint 报出来。**

**季度巡检**：
```
跑 harness_lint.py --only L008,L009,L010,L011
逐个处理：还清的 partial 改 accepted / 过期的行归档
```

## 7. 反模式（不要这么做）

| 反模式 | 现象 | 为什么错 |
|---|---|---|
| **AP-D1 决策只在聊天里定** | "我们上次说好了用 X" | 会话结束即消失；新 Agent 完全不知道 |
| **AP-D2 改了代码不更新决策** | 代码已按新方案，ADR 还是旧的 | Agent 读 ADR 会照旧方案干活（**比没有 ADR 更危险**） |
| **AP-D3 partial 不留 gap** | 标了"已决"但实际没做 | 新 Agent 以为已生效（`ADR-012` 就是这个形态） |
| **AP-D4 只删旧 ADR 不写指针** | 旧文件消失，引用处变死链 | 无法追溯"为什么改的"，且断链无提示 |
| **AP-D5 废止规则留在权威文档** | 宪法里留着"已废止规则表" | Agent 不知道该不该遵守（UGSim 实测：17 行废止表留在宪法里） |
| **AP-D6 假设"文档写了就等于代码做了"** | 注释声称已隔离，代码里没有 | 见 `GLOBAL-LESSONS.md` 的 M0："注释不算数" |

---

## 8. 一句话总结

> **决策不是"写下来的文档"，而是"有状态、有指针、有欠账、有失效水位"的活对象。**
> 三件套：**台账管状态** · **指针管取代** · **依赖声明管失效**。
> 机器校验四条：**L008 指针完整** · **L009 台账一致** · **L010 引用失效** · **L011 gap 未填**。
