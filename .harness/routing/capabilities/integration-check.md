# 能力卡：integration-check（集成检查）

> **触发**：模块写完了要接入 / 怀疑没接上 / handler 没反应 / 数据没落库 / 加了功能但界面上找不到
> **核心**：Wiring Failure 的四类**全部能通过传统测试**。必须做行为验证，不能只看单测。

---

## 四类接线失败

| # | 模式 | 症状 | 一句话判据 |
|---|---|---|---|
| A1 | 幽灵订阅 | 注册了、配置里有、DI 容器里有，但**从不触发** | 它在触发吗？ |
| A2 | 空执行 | 触发了、日志有了、健康检查 HEALTHY，但**没产出有用的东西** | 它在写吗？ |
| A3 | 伪造输出 | 数据按时落地、形状对、值还变，但**从没被计算过**（fallback 一直在写） | 输出是真的吗？ |
| A4 | 单调化 | 每条单独合法，整体收敛到极窄区间 | 输出有多样性吗？ |

---

## 三个探针（按成本从低到高）

### 探针 1 · write-read-reload（最便宜，一分钟内）

```
造一条数据 → 关闭页面/会话 → 重开 → 还在吗？
```

不在 = 没有持久化，**其他都是演戏**。这一个探针就能分清真系统和漂亮前端。

### 探针 2 · 让缺失层响亮失败

```
指向一个不存在的依赖 / 发畸形输入 / 请求中途断网
```

- **真系统**：以你能读懂的方式报错
- **stub**：返回它的固定答案，什么都不说

**"不报错"本身就是最强的信号** —— 说明它根本没去访问真实依赖。

### 探针 3 · 输出真的在变吗

```
改输入 → 输出是否相应变化？
连续多次运行 → 输出是否有合理多样性？
```

永远返回同一个值 / 收敛到极窄区间 = **什么都没算**。

## 工具

```bash
# 静态检查：新模块是否真的被主流程引用（找出"写了没人调用"的孤儿模块）
python scripts/check_integration.py <code_root>

# 参数
python scripts/check_integration.py <code_root> --entry <入口文件或目录>  # 指定主流程入口
python scripts/check_integration.py <code_root> --json                    # 结构化输出
```

脚本做什么：从入口（默认取配置里的 entry）做可达性分析，
报告**从未被任何地方 import/调用**的模块文件——这些就是 Wiring Failure 的静态嫌疑犯。

> ⚠️ 静态可达性**只能发现"完全没被调用"的模块**，抓不到"注册了不触发"和"写了没人读"。
> 那两类必须靠上面的探针（行为验证）。**工具 + 探针，缺一不可。**

---

## 排查清单（模块加了没反应，按顺序查）

```
□ 它在主流程里有调用点吗？（grep 引用 / 跑 check_integration.py）
□ 它注册了吗？（配置、DI 容器、路由表、事件订阅表）
□ 注册的名字对得上吗？（表名、事件名、枚举值，跨模块是否一致）
□ 触发条件成立吗？（事件真的被发出去了吗）
□ 执行时有异常被吞掉吗？（查日志；临时把 except 去掉看真实错误）
□ 产出写到哪了？有消费者读吗？（表名是否匹配）
□ 输出是算出来的还是 fallback？（关掉真实计算路径，看是否还在产出）
```

## 预防（比事后排查便宜）

1. **集成写进每个任务的 DoD**（AC-03「在 UI 上能点到」）—— 不要留到最后
2. **Phase 0 Walking Skeleton** —— 第一天就把每一层连通，之后只是往骨架上加肉
3. **跨模块字段先对齐再实现** —— 表名、事件名、枚举值各自猜测是空执行的主因
