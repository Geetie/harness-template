# 能力卡：delivery-audit（交付自查）

> **触发**：要交付 / 被问"做完了吗" / 怀疑交出来的是 demo / 收尾阶段
> **核心**：把「完成」从主观判断变成客观闸门。详见 `../../delivery/README.md`

---

## 30 秒快速判定（任一为"否" → 不是可交付状态）

1. **能手动走通吗** —— 每条核心用户旅程，你能从入口点到结果吗？（不是 curl，是点）
2. **数据存住了吗** —— 关掉重开，数据还在吗？
3. **模块接上了吗** —— 新写的模块，在 UI 上有入口吗？还是只有单测能调到？
4. **有占位吗** —— `python scripts/no_placeholder_guard.py <dir>` 通过吗？
5. **有证据吗** —— 每条 AC 能拿出命令输出 / 查询 / 日志吗？

---

## 完整自查（交付前逐条）

### A. 接线体检（专治 Wiring Failure）

对每一个注册的服务 / handler / 订阅：

```
□ 它真的被触发过吗？（查运行日志，不是"应该会"）
□ 触发后真的产出东西了吗？（查下游表/文件/接口）
□ 产出是算出来的，还是 fallback 写的？（改输入看输出是否变化）
□ 有消费者在读它写的东西吗？（写了没人读 = 白写）
```

### B. 隐形层六项（专治 Production-Readiness Cliff）

```
□ 持久化：真实存储 + 迁移脚本
□ 鉴权：真的拦截（用未授权账号实测）
□ 密钥：只在服务端，不在前端产物 / 仓库 / 日志
□ 并发：两个用户同时操作不互相覆盖（实测）
□ 可观测：出问题时能定位
□ 部署：有部署路径 + 回滚方案 + 健康判断
```

### C. 占位与假数据

```
□ 无 TODO / FIXME / NotImplementedError / 空函数体
□ 无 mock / fake / 硬编码常量充当真实数据源
□ 无 except: pass、无「log 后原样重抛」
□ 每个任务至少 1 条错误路径 + 1 条边界测试
□ 至少 1 条走真实依赖的集成测试（不全是 mock）
```

---

## 独立审计（必须在新会话跑）

用 `../../delivery/audit-prompt.md`，产出四态报告：
`PASS / FAIL / UNKNOWN / HUMAN_REVIEW`。

**铁律**：不得把缺失证据记为 PASS；不给部分分；审计者不改代码。

---

## 判定

| 结论 | 条件 |
|---|---|
| **可交付** | 五问全"是" + A/B/C 全通过 + 独立审计无 FAIL |
| **有条件交付** | 有 UNKNOWN 或一般缺陷，已登记 issue 且明确接受 |
| **不可交付** | 有阻断项：手动走不通 / 数据不落库 / 有占位实现 / 有 FAIL |

---

## 最容易自欺的三句话

| 自欺 | 真相 |
|---|---|
| 「测试全绿」 | 测试可能是镜像的；handler 从不触发也能全绿 |
| 「代码写完了」 | 写完 ≠ 接上 ≠ 能用 |
| 「应该没问题」 | 「应该」不是证据。拿日志来 |
