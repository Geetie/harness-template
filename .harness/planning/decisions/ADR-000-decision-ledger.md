# ADR-000 · 采用"决策台账 + 状态机 + 失效水位"管理决策演进

> **状态**：已接受（Accepted）· 2026-09-14
> **关联**：`.harness/DECISION-PROTOCOL.md` · `.harness/planning/DECISIONS.md`
> **一句话**：决策是有状态的活对象，用台账管状态、指针管取代、依赖声明管失效。
> **说明**：本 ADR 既是模板的**示例**（演示状态机怎么用），也是模板自身的**真实决策**。

---

## 1. 背景（Context）

### 1.1 问题

项目从零开始演进，决策与设计持续变化。此前模板只规定了「决策文档怎么写」，**没规定「决策怎么活」**——于是产生三个后果：

| 症状 | 实测证据（UGSimulator，12 条 ADR） |
|---|---|
| 不知道决策落地没有 | `ADR-012` §5 验收标准 5 条全未勾选；§4 明说"留到 Gap 3 一并做" |
| 不知道哪条决策还有效 | 12 条 ADR **无一标注 superseded**；旧的新的并存 |
| 不知道影响面有多大 | 文档没有依赖声明，改了决策不知道要更新哪些文档 |

### 1.2 触发原因

用户 2026-09-14 提出：**"进行了架构设计的升级，即使是昨天的文档，也已不可再用，过时了。如何能保证任意 Agent 接手，通过 Harness 工程文档了解项目时，了解的都是最新的信息？"**

### 1.3 约束

- 不能靠人记（纪律反复失效已被反复证明）
- 不能一步到位上强门禁（会因误报被关掉，违背"降噪即有效性"）
- 必须兼容小项目（可插拔，见机制 C）

---

## 2. 决策（Decision）

### 2.1 一句话决策

> **决策记录必须带状态（五态之一）、取代指针（双向）、落地证据（可核验）；文档通过 `depends-on` 声明依赖，被依赖决策失效时文档自动标 STALE。**

### 2.2 细则

| 项 | 规定 |
|---|---|
| **单一权威源** | `.harness/planning/DECISIONS.md` 的 §1 状态表。判断状态**只查此处** |
| **状态五态** | `proposed` / `accepted` / `partial` / `superseded` / `rejected` / `deprecated` |
| **partial 必带 gap** | 状态为 `partial` 时 `gap` 与 `blocked_by` 必填，否则 L011 报 ERROR |
| **取代必双向** | 旧写 `superseded_by`，新写 `supersedes`，缺任一侧 L008 报 ERROR |
| **失效水位** | 文档头部 `depends-on: ADR-NNN`；依赖了失效决策的文档自动标 STALE（L010） |
| **废止不留在权威文档** | 废止项移入 `archive/`，原位留一行指针 |

### 2.3 执行约束

- `harness_lint.py` 新增 L008（指针完整）/ L009（台账一致）/ L010（引用失效）/ L011（gap 未填）
- L008/L009/L011 为 **error**（进 pre-commit 拦截）；L010 首轮为 **warn**（先可见，稳定后升格）
- `AGENTS.md` 增加"动手前先读台账"准则

## 3. 否决项（Rejected Alternatives）

### 3.1 "靠人/Agent 自觉，每次决策变更时手动去改受影响文档"

**否决**。实测反例：UGSim 的元规范 147 行比宪法 145 行还长、"已废止规则表"17 行留在宪法里——**说明"记得去改"这件事在长期项目中必然失效**。必须靠机制检测。

### 3.2 "决策变更时直接删除旧文档"

**否决**。理由三条：① 引用它的地方会变成死链且无提示；② 丢失"为什么改"的追溯价值；③ **"还在但头顶有 STALE 警告"比"不见了"更安全**——Agent 能看见坑，而不是无声地读到过时内容。

### 3.3 "第一步就上强门禁（L010 也拦提交）"

**否决**。历史项目升级时会一次报几十条，按"降噪即有效性"原则，**噪音淹没真报警 → 门禁被关掉 → 等于没有门禁**。L010 首轮只 warn。

## 6. 后果（Consequences）

**正面**：
- 任意 Agent 接手时，读台账即知全部现行决策及其状态
- 决策被推翻时，受影响文档**自动显形**（不靠人记）
- `partial` 欠账集中可见，能被后续任务顺手还清

**负面/代价**：
- 多了一层"落台账"的动作（但 pre-commit 可强制，且比事后追溯便宜）
- 决策多时台账会变长（缓解：台账是**表**，一行一条，不用详述理由）

**对未来决策的约束**：
- 任何新政架构决策**必须**落台账并写状态，不得只在聊天里定
- 不得在权威文档里保留废止规则（会触发 `GLOBAL-LESSONS.md` A1）
