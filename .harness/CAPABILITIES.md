# 能力清单 —— 这套 harness 到底能防什么

> **读法**：每一行都标了三件事 —— **防什么** / **前提**（什么时候才成立）/
> **验证**（怎么测过的）。
>
> ⚠️ **最重要的提醒**：标「未实测」的项表示"代码写了但没验证过它真的拦得住"。
> 本项目已有多次教训：「声称能拦」≠「真能拦」（见文末 §已知的洞）。

生成方式：从各脚本**代码里抽取**（不是凭记忆），版本 v1.6.0。

## 0. 总览

| 触发点 | 对应脚本 | 性质 |
|---|---|---|
| **提交时**（pre-commit） | `.githooks/pre-commit.py` | 5 道，**强制** |
| **交付前**（手动/CI） | `evidence_gate.py` / `check_integration.py` / `test_audit.py` | 按需，可做门禁 |

| **体检**（手动） | `init.py` / `harness_lint.py` / `state_health.py` | 环境健康 |

## 1. 提交时强制拦截（pre-commit，5 道）

| # | 防什么 | 前提 | 验证 |
|---|---|---|---|
| 1 | **改了代码不更新 harness 状态**（progress.md / lessons.md 未同 commit） | 有 `.harness/config.json` | 端到端实测（多次提交被拦） |
| 2 | **提交占位实现**（TODO/桩/假数据/吞异常…11 条规则） | 配了 `code_root` | ✅ 双向：垃圾 demo 过（无关键词）+ 规则对照 4/4 |
| 3 | **代码风格不合规**（lint + format） | 配了 `quality` 段 | ✅ 阴性对照：本机没装的工具 → 正确显示"跳过"而非报错 |
| 4 | **只声明完成不给证据** | `feature_list.json` 被改动时触发 | ✅ 对抗测试 5/5 + 端到端 3/3 |
| 5 | **写了模块但没人调用**（孤儿/未接线） | 只要脚本存在；有 `entry` 更精确 | ✅ 双向：模板自身 0 误报 / 真孤儿被检出 |

**豁免**：`HARNESS_SKIP=1 git commit` 可整体跳过（合法用于纯格式化提交）。
**代价**：这个后门存在 —— 任何 Agent 都能用它绕过全部 5 道检查。

## 2. 反占位符（no_placeholder_guard，11 条）

防「看起来写完了，其实是空壳」。

| 级别 | 规则 | 防什么 |
|---|---|---|
| error | `todo-marker` | TODO / FIXME / HACK / TBD |
| error | `todo-marker-zh` | 中文未完成标记（需在注释中） |
| error | `not-implemented` | `NotImplementedError` 等 |
| error | `stub-return` | 返回硬编码假数据字符串 |
| error | `stub-variable` | 假数据变量（mock_data / 假数据） |
| warn | `stub-return-dict` | 返回的对象字面量里带 mock/fake 值 |
| warn | `empty-body` | 空函数体（`pass` / `...`） |
| warn | `shallow-catch` | 吞异常（catch 后什么都不做） |
| warn | `log-and-rethrow` | 无上下文的原样重抛 |
| warn | `demo-wording` | 演示/临时话术 |
| warn | `hardcoded-fallback` | 带注释的兜底返回 |

**前提**：只在配了 `code_root` 的目录下扫。

**验证状态（分两级，别混）**：
- ⚠️ **9 条规则未逐条验证** —— 只跑过整体（模板自身 0E/0W），
  没有为每条构造正反样本测过误报率
- ✅ **2 条经过修正验证**：`todo-marker-zh`（移除"占位符"后不再误报）、
  `log-and-rethrow`（放宽判据后双向对照 4/4）
- ✅ 实测垃圾 demo（`return 0.0`）**放过** —— 因为它不含任何关键词

→ **能力边界：只查「字面标记」，查不了「实质为空」。**
`return 0.0` / `return {}` 这类无标记的假实现，它抓不到。

**规则精度修正记录**：
- `todo-marker-zh` 曾含"占位符"（名词），导致注释里**讨论**占位符就误报 9 条 → 已移除
- `log-and-rethrow` 曾把 `raise Err(f"...{e}") from e`（包装并加上下文）误判为占位式重抛 → 判据已放宽为「raise 后跟标识符+括号+内容」

## 3. 证据门禁（evidence_gate）

防「标 completed 但其实没做完」。**这是针对"假完成"的主力。**

### 3.1 结构防线

| 防线 | 说明 |
|---|---|
| 必须有证据 | `completed` 却没有 `evidence` → 拦 |
| 证据必须具体 | `expect_stdout` 空 / 全是通用词（ok、成功）/ 无数字 → 拦 |
| evidence 路径必须存在 | 字符串形式指向不存在的路径 → 拦 |
| **强度锁** | completed 数下降 → 拦（防"改回 missing 清理告警"） |

### 3.2 运行时防线（真的执行证据）

| 防线 | 说明 |
|---|---|
| 退出码匹配 | 实际退出码 ≠ `expect_exit` → 拦 |
| 输出含期望串 | 输出里找不到 `expect_stdout` 的每个串 → 拦 |
| 产物存在且非空 | 缺失或 0 字节 → 拦 |
| **产物必须是本次产出** | 执行前后 size+mtime 完全没变（复用旧文件）→ 拦 |
| **touches 必须被真实调用** | `sys.settrace` 观测：只 import 不调用 → 拦 |

**前提**：
- 证据命令形如 `python xxx.py` → **走运行时探针**（强）
- 其他形式（pytest / node / go test）→ **降级为静态检查**，且**明确打印"未做运行时验证"**
- 强度锁需要先 `--update-lock` 建立基线

### 3.3 对抗测试结果（14 种造假手法）

**拦住 13 种**：无证据 / 通用词期望 / 空期望 / 期望值不符 / 不引用 /
假引用(import 不用) / cmd 非脚本 / 假产物 / 空产物 / 假 touches /
降分母 / 双向都假 / 复用旧产物

**放过 1 种（真边界，承认）**：
```
def total():
    return 42.0     # 硬编码，但值恰好等于期望 + 证据真的调用它
```
→ 行为与期望一致，**这不是造假**。门禁管行为，看不出"实现方式是否合理"。

## 4. 接线检查（check_integration）

防「写了模块但没接进调用链」。

| 模式 | 触发条件 | 原理 | 精度 |
|---|---|---|---|
| **入口可达性** | 探测到入口 / 配了 `--entry` | 从入口出发做引用可达性分析 | 高（但依赖 import 解析准确） |
| **入度=0**（降级） | 探测不到入口时自动启用 | 没被任何其他源文件 import | 中（不依赖入口，但判据粗） |

**豁免**（避免噪音，四类）：
1. 包与基建：`__init__.py` / `conftest.py` / `setup.py` / `manage.py` / `settings.py` / `wsgi.py` / `asgi.py`
2. 工具脚本目录：`scripts/` `tools/` `bin/` `cmd/` `cli/`
3. 含 `if __name__ == "__main__"` 的文件
4. 白名单：`config.json` 的 `integration.allow_orphans`

**验证**：
- ✅ 正向：模板自身 16 个 CLI 脚本 → **0 误报**
- ✅ 反向：真实项目里未被引用的 `reporting/exporter.py` → **检出并阻断**
- ✅ 端到端：真实 commit 被拦，输出明确列出「接线检查未通过」

**已知局限（重要）**：
- 只能发现「**完全没被调用**」。「注册了但不触发」（幽灵订阅）、
  「触发了但写到没人读的地方」（空执行）**抓不到** —— 需行为验证
- import 解析失败时会误判 → 输出里有 WARN 说明（"相关模块可能被误判为孤儿"）

## 5. 代码规范（quality）

防「风格不一致 / 工具没接上」。

| 键 | 会改文件? | 何时跑 |
|---|---|---|
| `typecheck` | 否 | `--check` |
| `lint` | 否 | `--check` / `--staged` |
| `format_check` | 否 | `--check` / `--staged` |
| `lint_fix` | **是** | 仅 `--fix` |
| `format_fix` | **是** | 仅 `--fix` |

**前提**：`config.json` 有 `quality` 段（由 `--stack` 生成）。
**验证**：✅ 阴性对照 —— 塞入未安装的 `golangci-lint` → 正确显示「跳过 + 安装提示」，exit 0（不是"命令失败"）。

**能力边界**：工具没装时**跳过**，所以"没报错"可能是"没检查"。
但会明确打印跳过原因，不静默。

## 6. 测试有效性（test_audit）

防「测试跑了但没验证」。依据 arXiv:2606.18168 的 8 类 oracle 分类法。

| 级别 | 类别 | 含义 |
|---|---|---|
| 弱 | W1 | 无断言 —— 只调用不验证 |
| 弱 | W2 | 只查存在/非空 |
| 弱 | W3 | 只做布尔断言，不比值 |
| 弱 | W4 | 只验证 mock 被调用 |
| 弱 | W5 | 只做快照匹配 |
| 强 | S1 | 值相等/比较 |
| 强 | S2 | 错误、包含或类型检查 |
| 强 | S3 | 两种以上不同强信号 |

另检测**孤儿测试**：测试文件 import 了不存在的模块（被测代码已删但测试还在）。

**前提**：默认 `exit 0`（**只报告不拦截**）。要拦需显式 `--fail-on weak` 或 `--fail-on orphan`。
**验证**：✅ 分类器逐类对照 **8/8**（含修正一处真 bug：W3 判据用 `all()` 漏判 `assert ok == True`）。

**能力边界**（论文自述）：只查**语法信号**不查语义；
「判为 S1 只说明存在相等性比较，不说明比的是不是正确的属性」；未覆盖隐式 oracle。

## 7. 测试运行（test_runner）

防「每次跑全量 / 没有进度 / 不知哪项慢」。

| 能力 | 说明 |
|---|---|
| **默认只跑受影响的** | 按 git 改动 + 反向引用映射选测，**显式打印选了哪些、为什么** |
| 跑不出映射时 | 工作区干净 → 明确报「无需跑测试」；只改文档 → 报「不影响代码测试」 |
| `--layer` | 按 marker / 目录分层跑 |
| `--slow` | 报告最慢的测试 |
| `--report` | 生成测试汇报骨架 |
| 进度 | 默认 `-v` 逐项 + 自动检测 pytest-sugar；**会把配置里的 `-q` 换成 `-v` 并说明** |

**安全规则**：跑子集时**必打印**"这是子集，merge 前跑 `--all`"（TIA 通行纪律：selects, not replaces）。
**验证**：✅ 3 场景实测（干净 / 改 py / 改文档）。

**能力边界**：选测映射是**启发式的**（模块名反向引用），可能漏 —— 所以才有全量兜底提醒。
**未验证**：映射的**召回率**没测过（真实项目里"改了 A 却只该跑 B"的情况有多少能覆盖）。

## 8. 设计债信号（design_smell）

防「积重难返的结构问题」。**输出一律 warn，不是违规。**

| 信号 | 阈值 |
|---|---|
| SM001 god-module | 文件 > 500 行 或 顶层定义 > 20（TS: export > 20） |
| SM002 circular-import | 存在模块环 |
| SM003 deep-nesting | 逻辑嵌套 > 4 层（用 ast 算，**非物理缩进**） |
| SM004 long-params | 参数 > 5 |
| SM005 god-class | 类方法 > 15 |

**验证状态**：
- ✅ SM003 经过精度修正验证：最初按物理缩进算 → ruff 格式化后的续行被误判，
  **363 条信号里 359 条是噪音**；改用 ast 逻辑嵌套后降到 **31 条**
- ✅ 模板自身实测 —— 检出 `harness_lint.py` 1260 行等真债
- ⚠️ **阈值未校准**：500 行 / 20 个定义 / 5 个参数 是拍定的，
  没有用真实项目分布验证过它们的误报率

| L005 | 文档过期（"最后更新"超阈值） |
| L006 | 阅读清单过长（token 黑洞） |
| L007 | 占位符残留（`{{XXX}}` 未填） |
| L008 | 失效决策缺双向指针（superseded_by / supersedes） |

**未逐条验证** —— L001-L011 没有为每条构造正反样本，
所以各条的误报率是未知的（L001 曾误报过"文档里举例提到 pyproject.toml"）。

## 11. ⚠️ 已知的洞（以为能防但实际不能）

**这一节比上面所有节都重要。**

| 洞 | 说明 |
|---|---|
| **假完成（行为对但实现假）** | `def total(): return 42.0` 硬编码 + 证据真调用 → 通过。门禁管行为不管审美 |
| **未集成的两种形态** | 「注册了但不触发」「触发了但写到没人读的地方」→ 静态分析抓不到 |
| **HARNESS_SKIP=1 后门** | 一个环境变量绕过全部 5 道提交检查 |
| **非 Python 项目的证据** | 探针只支持 Python；pytest/node/go test 走静态检查（已标注但确实弱） |
| **test_audit 默认不拦** | 它只报告。不配 `--fail-on` 就等于没有门禁 |
| **guard 只见标记不见实质** | `return 0.0` 无标记 → 放过 |
| **证据可被"一起造假"** | 假实现 + 假证据脚本互相引用，理论上仍能过（虽然伪造成本已高于真做） |
| **未实测的项** | 本文档中未标 ✅ 的规则，只有代码没验证 —— 按本项目惯例，**未验证≈不可信** |

### 更根本的一条

> **门禁强度 = 它的"不可自证性"。**
> 凡是 Agent 能自己满足的条件（自己写 status、自己写证据、
> 自己声明 touches），就总能被"满足而不产生实质"。
> 真正硬的只有两种：**外部系统的观测**（真实用户、第三方 API 的响应）
> 和**独立于实现者的判断**（人看代码）。

## 12. 怎么复验（别信我说的，自己跑）

```bash
# 反占位符：造个垃圾实现，看放不放
python scripts/no_placeholder_guard.py src

# 证据门禁：对抗测试（14 种造假手法）
python <模板>/_adv_test.py

# 接线检查：双向
python scripts/check_integration.py src        # 看孤儿
python scripts/check_integration.py src --json # 机器可读

# 代码规范
python scripts/quality.py --doctor             # 哪些工具装了

# 测试有效性
python scripts/test_audit.py tests             # oracle 分布

# 全部门禁
python scripts/init.py                         # 38 项体检
python .githooks/pre-commit.py                 # 5 道提交检查
```

**复验原则**（本项目踩出来的）：**任何"它能拦住 X"的说法，都要有
①正向（该拦的拦住了）②反向（不该拦的放过了）两个方向的实测。**
只有单向验证的结论，默认不可信。
