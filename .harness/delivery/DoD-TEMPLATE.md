# Task DoD 模板

> **用法**：每个任务开工前，复制本模板填进任务卡（或 `planning/` 的 tasks 文件）。
> **八项全打勾才算 done**，缺任何一项 = 未完成。

---

## 模板（复制这段）

```markdown
### T0XX  <一句话：用户能走完的一条路径>

**路径**：<起点> → <经过哪些层> → <用户看到什么>
**涉及模块**：<目录/文件清单>

**AC（验收标准）**
- [ ] AC-01 走通：<具体动作> → <具体可观察结果>
- [ ] AC-02 持久化：关掉页面 → 重开 → 数据还在（write-read-reload）
- [ ] AC-03 集成：在 **UI 上能点到**，不是只能靠 curl / 单测调用
- [ ] AC-04 错误路径：<异常输入> → 明确提示，不 500、不静默、不吞异常
- [ ] AC-05 边界：<空 / 超大 / 非法> → 明确拒绝，不崩溃
- [ ] AC-06 测试：≥1 条**走真实依赖**的集成测试（真实 DB / 文件 / 网络），不全是 mock
- [ ] AC-07 无占位：`python scripts/no_placeholder_guard.py <dir>` 通过
- [ ] AC-08 质量：`python scripts/init.py` + 类型检查 / lint / 测试全绿（附真实输出与退出码）

**证据**
- 测试命令 + 实际输出 + 退出码：
- AC-02 验证方式（截图 / DB 查询）：
- 未满足项（标 UNKNOWN + 原因）：
```

---

## 各项的理由（不要跳过任何一项）

| 项 | 防的是什么 | 跳过会怎样 |
|---|---|---|
| **AC-01 走通** | 基本功能存在 | — |
| **AC-02 持久化** | Production-Readiness Cliff | 演示时漂亮，刷新后数据没了 |
| **AC-03 集成** | Wiring Failure | 模块写好了但没人调用，等于没写 |
| **AC-04 错误路径** | 浅层错误处理 | 真实环境第一个异常就崩，或更糟：静默错误 |
| **AC-05 边界** | happy-path 偏食 | 空输入 / 超大文件 / 非法 ID 直接 500 |
| **AC-06 真实依赖测试** | 镜像测试 | 测试绿但生产路径根本没跑通（mock 骗了自己） |
| **AC-07 无占位** | Incomplete Implementation | TODO 变成交付物 |
| **AC-08 质量闸门** | 基线漂移 | 改动破坏其他模块而不自知 |

---

## AC 的四条写法要求

1. **具体** —— 「搜索能用」❌ / 「搜关键词返回匹配项、按最近排序、200ms 内」✅
2. **可测** —— 每条都能想到一个可执行的检查
3. **独立于实现** —— 「用二分查找」❌ / 「1 万条内 200ms 返回」✅
4. **Agent 精确优化你写的标准，不多不少** → **未写出的标准 = 未满足的标准**

---

## 给 Agent 派活时的 prompt 模板

```
读 <spec 路径>，把它当作本次会话的权威契约，不得偏离其中的数据契约与行为边界。

任务：T0XX <描述>

验收标准（全部满足才算完成）：
- AC-01 … AC-08（见上）

完成前必须：
1. 实际运行类型检查 / lint / 测试，贴出真实输出与退出码
2. 逐条对照 AC 给出证据；无法验证的标 UNKNOWN
3. 不写 TODO、不加占位实现；缺依赖就显式报错

不要说「已完成」，说清：改了什么 / 测了什么（附输出）/ 每条 AC 的证据 / 还剩什么不确定。
```
