# 分层 AGENTS.md 书写规范

> **为什么分层**：根目录 AGENTS.md 是宪法，不可能也不应该包含每个目录的细节。
> 在每个代码子目录放一份 ~20 行的 `AGENTS.md`，Agent 改哪个目录就读哪一份——**既不占全局 token，又能就近治理**。

---

## 四段式模板（每个模块 AGENTS.md 照抄这个结构）

```markdown
# AGENTS.md — <目录名>

## 职责
<这个目录做什么，一段话；不做什么，一句话>

## 关键文件
| 文件 | 作用 |
|---|---|
| `xxx.ts` | <一句话> |

## 约束
- <这个目录特有的红线，如"不许直接 import 上层"、"必须走某某入口">
- <如无，写"遵循根 AGENTS.md §4">

## 测试
`命令`（当前基线：N passed / M failed）
```

---

## 书写五原则

1. **~20 行封顶** —— 超了说明该拆目录，或该把内容外推到 skill
2. **只写 Agent 猜不到的** —— 目录职责、跨文件约束、隐式约定；不要写"这是 TypeScript 文件"
3. **约束要可执行** —— 「不许直接 import 上层模块」✅ / 「保持代码整洁」❌
4. **基线要写数字** —— 「测试 N passed / M failed」，不含糊
5. **变更即更新** —— 改了这个目录的代码，同一 commit 更新这里的"关键文件"与"测试"

---

## 何时新增一份

- 新建代码目录时**立即**创建（不然后人无从下手）
- 目录职责发生实质变化时重写
- 目录删除时删除对应文件（不要留孤儿）

---

## 常见错误

| 错误 | 后果 | 正确做法 |
|---|---|---|
| 把架构说明抄进去 | 与根 AGENTS.md 重复，两处漂移 | 只写本目录特有内容，架构指针回根文件 |
| 写"最近变更"长段落 | 迅速过期，变成噪音 | 变更记 `state/progress.md`，这里只记稳定事实 |
| 没有约束段 | Agent 自由发挥，破坏分层依赖 | 至少写明依赖方向（能 import 谁、不能 import 谁） |
| 测试基线不写数字 | 无法判断回归 | 写具体数字与命令 |
| 超过 40 行 | 占 token 且没人读 | 拆分目录或外推 skill |
